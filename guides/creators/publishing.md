# 发布与更新作品

[返回创作者指南](README.md) · [收录模板](../../CONTRIBUTING.md)

适用版本：**0.29.0**。源码核对，未重新实机验证；[版本依据](../../MAINTAINING.md)。

## 整理身份与版本

从工程或导出包的 `mod.json` 核对 ID、名称、作者和版本。ID 用于安装包身份、依赖和目录去重；版本用于区分发布内容，作品改名时通常继续使用原 ID。

同 ID 导入会走替换确认。不要为了更新文件名就改 ID，也不要在不同包之间复用其他作品的 ID。内容变更后更新 Mod 版本，并保留更新说明。

游戏适用版本和平台是需要作者单独说明的兼容信息，不是当前清单中自动提供的字段。`runtimeApiVersion` 也不是面向玩家的游戏版本号。

## 前置与资源

列清每个前置 Mod 的 ID、版本要求和作者发布入口。当前清单的依赖版本为非空时按精确版本匹配；空版本表示接受任意已安装版本，但是否实际兼容仍需作者验证。

工程内资源引用应随包可用，避免依赖作者电脑的绝对路径。关卡需要加入选择目录，目录中的 SaveKey 要唯一、普通难度要绑定到对应关卡。借用其他 Mod 的资源时按要求声明前置，而不是只在自己的电脑装好后就认为包完整。

## 发布前自检

- 导出确实成功，并确认将发布的是本次生成的 `.pmod`。
- 在只启用本作品及必要前置的环境中，从安装包完成冷启动和实际加载。
- 在不依赖作者源工程目录的环境中验证包内资源可用。
- 走通玩家会使用的入口和关键玩法；含关卡时检查选关、开局、结算及再次启动后的进度。
- 检查更新、停用与再次启用的结果，记录有影响的兼容变化。
- 分别验证声明支持的平台；未验证的平台、联机组合和功能明确注明。

使用独立测试账号或备份自己的进度，避免把正在游玩的存档作为唯一验证环境。导出器检查通过不替代完整玩法验证。

## 发布页面写什么

| 项目 | 建议内容 |
| --- | --- |
| 作品介绍 | 主要内容、截图或视频、游戏内使用入口 |
| 版本 | Mod 版本、适用游戏版本、发布日期和更新说明 |
| 平台 | Windows、Android 的支持依据与未验证项 |
| 安装 | `.pmod` 下载入口、前置依赖、特殊操作 |
| 兼容 | 已知冲突、联机说明、旧版本迁移注意事项 |
| 反馈与授权 | 作者反馈入口、使用与转载说明、源码是否公开 |

安装包由你自己的发布页面维护。为旧版玩家保留下载时，清楚标明其对应的游戏版本。若提供网盘，注明提取码和访问条件。

## 收录与后续更新

按 [收录规则](../../CONTRIBUTING.md) 提交 PR，或填写“申请收录 Mod”表单。发布新版本后更新原条目的版本、兼容信息、入口与核对日期；历史实测记录继续绑定原版本。

暂停维护时说明最后已知适用版本。需要撤下作品时，通过“更新或撤下条目”表单提供作者来源，由维护者核对后处理。
