# 前置依赖、冲突与联机

[返回玩家指南](README.md) · [管理 Mod](managing.md)

适用版本：**0.29.0**。源码核对，未重新实机验证；[版本依据](../../MAINTAINING.md)。

## 看懂版本信息

| 信息 | 含义 |
| --- | --- |
| 游戏版本 | 例如本指南对应的 0.29.0 |
| Mod 版本 | 作者为作品发布的版本，与游戏版本分别记录 |
| 前置版本 | 该作品需要的其他 Mod 版本 |
| 实测记录 | 在指定游戏、Mod 版本、平台和启用组合下验证了哪些步骤 |

当前依赖声明若指定非空版本，加载器要求精确匹配；不能自动理解为“这个版本以上”。目录应照实记录作者要求。前置需要安装且启用，改文件名不会改变包内 ID 或依赖关系。

## 遇到依赖或冲突

先打开 **Mod 管理 → 选择作品 → 更多 → 查看诊断**，确认问题是缺少前置、版本不符、重复 ID，还是多个作品发生冲突。

按提示补齐前置、选择正确版本或停用冲突作品，再重启检查。不要通过改文件名或修改包内清单来宣称已经解决冲突。

目录中的“已知冲突”是已经报告的情况；没有记录不等于任意组合都能共存。

## 联机前准备

1. 各方核对游戏版本，并按作者说明确认作品支持当前联机玩法。
2. 使用相同来源的安装包，统一需要启用的 Mod 和前置，重启确认加载完成。
3. 联机校验不通过时，以游戏显示的具体差异排查，再重新尝试。

仅有相同作品名或相同 Mod 版本不足以保证一致：游戏还会核对安装包内容、实际加载模式及顺序等信息。作者重新打包却没有改版本时，也可能产生不同安装包。

“允许进入联机”只表示当次环境检查满足要求；具体玩法仍需要对应版本的多人实测。目录的联机记录应说明人数、平台、启用组合、操作步骤及结果。
